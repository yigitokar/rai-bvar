\section{Using \pkg{rai-bvar}: a walk-through}\label{sec:walkthrough}

Two short scripts show the user interface on simulated data, a stationary three-variable quarterly
VAR(1) for output growth, inflation and an interest rate, stored as raw levels with FRED-style
transformation codes, so they run without network access.
The listings are verbatim excerpts with the scripts' own line numbers; \cref{app:walk-output}
gives the scripts and their output in full (the MCMC output is bitwise reproducible only on the
same platform and package versions; \cref{sec:architecture}).
% [V] docs/paper/code/{ex_a,ex_b}.py, out/{ex_a,ex_b}.txt, out/env.json (d58c9ef, macOS arm64); identical to dossier 02 §13 outputs at 62d15f6

\subsection{Data}\label{sec:walk-data}

\code{VARData.from_frame(raw, tcodes={...})} takes raw levels indexed by dates or periods, rejects
malformed input and uses the column order as the recursive ordering of every triangular model;
\code{upto}, \code{tail}, \code{select} and \code{realized} give the data available at an origin,
rolling windows, reorderings and future outcomes (\cref{app:data}).
% [V] tests/unit/test_dataset.py::test_interior_missing_value_raises; dossier 02 §9.1; src/rai_bvar/data/dataset.py l.215-237 at d58c9ef
The transformation codes 1--7 are those of FRED-MD and FRED-QD \citep{mccracken2016fredmd,mccracken2021fredqd}, each
with a pathwise inverse, and they set the own-first-lag prior mean (1 for levels and log levels,
0 for differences).
\code{rb.datasets.load("fred-qd", vintage="2026-09")} downloads a pinned vintage of FRED-QD
\citep{mccracken2021fredqd}, checks its SHA-256 checksum and caches it; the files are not bundled.
% [V] src/rai_bvar/datasets/fred.py module docstring and load() (l.169-179) at d58c9ef; dossier 02 §9.5
% [R] codes 1-7 defined identically in McCracken & Ng FRED-QD (Review 103(1), p. 6 and Appendix p. 26) and FRED-MD (WP 2015-012B, data appendix): https://www.stlouisfed.org/-/media/project/frbstl/stlouisfed/publications/review/pdfs/2021/01/14/fred-qd-a-quarterly-database-for-macroeconomic-research.pdf; https://files.stlouisfed.org/files/htdocs/wp/2015/2015-012.pdf
The named FRED-QD variable sets load with the package's own codes by default
(\code{tcodes="rai"}), which differ from the benchmark codes
\citep[Table~A1]{mccracken2021fredqd} for price indices (5, log first differences, instead of 6),
for interest rates and the unemployment rate (1, levels, instead of 2) and for housing starts (4
instead of 5); \code{tcodes="official"} uses the codes in the file.
% [R] McCracken & Ng (2021) Appendix Table A1 (https://doi.org/10.20955/r.103.1-44; PDF above): GDPCTPI, PCECTPI, CPIAUCSL 6 (A1F, pp. 33-34); FEDFUNDS, GS1, GS10 2 (A1H, p. 36); UNRATE 2 (A1C, p. 29); HOUST 5 (A1D, p. 31); the transform row of the cached, checksum-verified 2026-09 file has the same codes; rai codes: src/rai_bvar/datasets/fred.py l.170-173 (default variables="small", tcodes="rai")

With \code{vol=SV()}, the default mean \code{Linear(prior=Minnesota())} moves to the MCMC engine,

% [V] out/ex_b.txt line 2; tests/unit/test_api_resolution.py::test_resolution_table
Its Minnesota hyperparameters are an empirical-Bayes plug-in from the conjugate twin on the same
window (for SV not a type-II maximum-likelihood estimate), so every volatility arm on that window
receives the same mean prior.
% [V] out/ex_b.txt line 3; tests/analytic/test_eb_mcmc.py::test_eb_plug_in_equals_the_phase1_eb_mode_at_cross_1
On this homoskedastic DGP the SV parameters $\phi_i$ and $\sigma_i$ mix slowly, and the fit is
flagged as not converged.
% [V] out/ex_b.txt summary table and "converged: False" (MCMCSettings(chains=4, draws=1000): 4 x 1000 kept draws)
The forecast container and its log-density interface are those of the analytic case (R3).
% [V] out/ex_b.txt lines "ForecastResult(...) | engine attr: mcmc" and the two LPD lines
In the final comparison, whose arms are structural Mode~I models that differ only in volatility,
SV has a $\Delta$LPD of $-0.11$ over 11 rolling-window origins with an MCSE of 0.10, too imprecise
for any verdict (one-sided DM $p$-value 0.421 for ``worse''; the reasons line prints the smaller
of the two one-sided values), and it converged at none of them, so the
convergence gate forces ``inconclusive'' whatever the other evidence says.
% [V] out/ex_b.txt axes lines; table row "Linear x SV 1" and reasons line ("converged at only 0% of origins")
This is intended: the gate refuses to certify a comparison with an unconverged fit (\cref{sec:cr}
shows how it decided a replication criterion and how a fit-level diagnostic set the MCMC budget).
