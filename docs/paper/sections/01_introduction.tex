\section{Introduction}\label{sec:intro}

% ---------------------------------------------------------------- P1: the question
\pkg{rai-bvar} is a Python package for Bayesian vector autoregressions (BVARs) built around one question, stated in its specification as
\begin{quote}
``Does added model complexity improve out-of-sample density forecasts once time-varying volatility is accounted for?''
\end{quote}
% [R] SPEC.md §1.1 (l.27-39), quoted verbatim
The qualification matters.
The volatility of U.S. macroeconomic shocks has changed over the post-war period \citep{cogley2005drifts,primiceri2005time,sims2006were}, and allowing for time-varying volatility has been found to improve BVAR density forecasts \citep{clark2011realtime,clark2015macroeconomic,carriero2016common}; \citet{chan2024bvars} surveys BVARs with stochastic volatility (SV), and \citet{carriero2015bayesian} study how other specification choices affect forecast accuracy.
When a richer mean or prior is compared with a baseline that also differs in volatility, the gain combines the two changes.
The package therefore adopts a design position, a rule of the software and not an empirical finding: a mean or prior effect is measured with the volatility specification held fixed, against the linear Minnesota model under the same SV and never against constant volatility. % [R] SPEC.md R2 "Volatility first (fair ablation)" (l.109)

% ---------------------------------------------------------------- P2: six threats (the thesis)
Our thesis is that such a comparison is only as credible as its weakest link.
We name six links as requirements on the software, not claims about existing tools, and say where each is addressed.
\begin{enumerate}
\item \emph{The sampler may target the wrong posterior.}
  A published equation-by-equation sampler for large BVARs with SV \citep{carriero2019large} did so, as \citet{bognanni2022comment} showed; \citet{carriero2022corrigendum} corrected it.
  Samplers need checks that are shown to catch known errors (\cref{sec:validation}).
\item \emph{Every forecast origin is a separate MCMC fit, and each must converge}; a gain computed from unconverged fits should not be certified (\cref{sec:eval-verdict,sec:validation-convergence,sec:replication-prereg}).
\item \emph{The log score is itself a Monte Carlo estimate.}
  At horizons beyond one step its error can be large in the tails while the reported standard error stays small (\cref{sec:eval-tail}). % [R] NOTES 8b (Clark--Ravazzolo crisis origins, h = 8)
\item \emph{Triangular SV models depend on the variable ordering} \citep{arias2023macroeconomic,chan2024large}, so a gain should be reported with its spread across orderings (\cref{sec:eval-ordering,sec:replication-results}).
\item \emph{Tests must be valid for the design.}
  For nested models under an expanding window, the tests of \citet{diebold1995comparing} lack their standard limit \citep{clark2001tests} and the framework of \citet{giacomini2006tests} needs a rolling or fixed window; the package then labels those $p$-values descriptive and decides through the model confidence set \citep{hansen2011model}, whose validity in that design is itself open, on proper scores \citep{gneiting2007strictly} (\cref{sec:eval-tests,sec:eval-verdict,sec:limitations}).
\item \emph{Analysis choices can be made after the scores are seen}, unless the settings are fixed in code before the scores exist (the pre-registration in \cref{sec:replication-prereg}).
\end{enumerate}
Two infrastructure requirements follow: one estimation interface and output format for conjugate and non-conjugate models (\cref{sec:arch-resolution,sec:eval-contract}), and no look-ahead, so that data-dependent prior settings such as Minnesota scales are recomputed inside every estimation window (\cref{sec:eval-backtest}). % [R] SPEC.md R9

% ---------------------------------------------------------------- P3: what rai-bvar is
The package metadata describe \pkg{rai-bvar} as ``Ablation-ready Bayesian VARs: composable mean, volatility and prior components with a fair out-of-sample verdict engine.'' % [V] pyproject.toml [project] description, verbatim
Five design commitments shape it:
(i)~the composition, never the user, chooses the engine, sending conjugate Minnesota models to an analytic engine and compositions with SV, outliers or Student-$t$ errors to hand-written JAX Gibbs samplers;
(ii)~both engines return one predictive contract;
(iii)~one backtest and one verdict engine score and compare every model;
(iv)~validation ships as library code, not only as tests;
and (v)~the implementation is licensed under Apache-2.0, with GPL-licensed packages run only as numerical oracles (qualified in \cref{sec:related}). % [V] SPEC.md R1, R3; src/rai_bvar/api.py (no user-settable engine field); src/rai_bvar/validation/; LICENSE
``Ablation-ready'' describes the architecture, in which a new mean, volatility or prior component is evaluated against every existing one through one contract and one verdict rule.
The release described here (Phases 0--2 of the roadmap) populates the volatility axis; the mean axis is linear and the prior axis is the Minnesota family (\cref{sec:framework}). % [V] dossier 01 §2.1; src/rai_bvar/validation/joint.py _COMPOSITIONS (l.455-483 at 7f410dc)
It is release 0.2.0 (tag \code{v0.2.0}), classified as pre-alpha: commit 4ac7969 of \url{https://github.com/yigitokar/rai-bvar} (\cref{app:repro}), with the code of commit 7f880e1, on which the release validation record was made; ``the release commit'' below refers to that code. % (stage 4: the definition of "the release commit" was added because the paper uses the phrase for 7f880e1, the commit of the validation record and of CI run 40061724239, and for 4ac7969; their code is the same) [V] git show 4ac7969:pyproject.toml (version = "0.2.0"; classifier "Development Status :: 2 - Pre-Alpha"); 4ac7969 = main after PR #10, whose only change to 7f880e1 is the version string (git diff 7f880e1 4ac7969: pyproject.toml, uv.lock, and the reports of PR #9 under benchmarks/reports/); tag v0.2.0 at 4ac7969 and its GitHub release were created on 2026-10-24 (git ls-remote --tags origin)

% ---------------------------------------------------------------- P4: contributions
\pkg{rai-bvar} makes each link checkable, and this paper shows the evidence for each.
The econometrics is not new; the contribution is the integration, the contracts and the evidence of correctness:
\begin{itemize}
\item \textbf{C1, a factorial composition grammar} (\cref{sec:architecture}).
  \code{BVAR(mean=...,vol=...,lags=...)} resolves to an engine by fixed rules and rejects invalid compositions at construction; \code{spec()}, \code{axes} and \code{spec_hash(model)} make ``differs along exactly one axis'' checkable. % [V] src/rai_bvar/api.py (BVAR.spec, BVAR.axes); src/rai_bvar/models/base.py l.57 (spec_hash is a module function, not a BVAR attribute); tests/unit/test_api_resolution.py::test_resolution_table, ::test_sv_arms_differ_from_constant_along_the_vol_axis_only
\item \textbf{C2, a populated volatility axis} (\cref{sec:framework}).
  Constant volatility under inverse-gamma, inverse-Wishart or IW-equivalent \citep{chan2022asymmetric} priors, and SV with AR(1) or random-walk log-variance, outliers \citep{carriero2024addressing}, Student-$t$ errors \citep{jacquier2004bayesian} or both, in two recursive structural forms and the corrected reduced form \citep{carriero2022corrigendum}, though not every combination in every form (\cref{sec:framework:delivered}); dummy-observation priors \citep{doan1984forecasting,sims1998bayesian,giannone2015prior} are available on both engines. % [V] src/rai_bvar/validation/joint.py _COMPOSITIONS (rows 1-18, 201-205; l.455-483 at 7f410dc); src/rai_bvar/api.py docstring (inverse-Wishart only in structural Mode II; reduced x Constant("iw") raises); dossier 01 §2.1
\item \textbf{C3, one predictive contract} (\crefrange{sec:eval-contract}{sec:eval-tail}).
  Path draws with per-draw conditional means and Cholesky factors give a Rao--Blackwellised log score and an effective-sample-size-adjusted Monte Carlo standard error (MCSE) \citep{geweke2010comparing,kruger2021predictive}. % [V] src/rai_bvar/forecast/result.py::log_pred_density (delta-method MCSE times sqrt(S/ESS) on MCMC forecasts, l.323-338); tests/contract/test_forecast_contract_mcmc.py::test_log_pred_density
  We diagnose its tail failure at $h>1$ and implement, for MCMC forecasts, an opt-in estimator that integrates the intermediate outcomes out given each draw's volatility path, conditioning as \citet{hiraki2026dynamic} do for predictive moments. % [R] Hiraki, Chib & Omori arXiv 2604.04529v1 App. D (https://arxiv.org/html/2604.04529v1); prior art: sec:eval-tail; NOTES 8b; [V] D-34 tests at b9c66c0 (tests/unit/test_lpd_integrated.py, tests/mcmc/forecast/test_lpd_integrated_mcmc.py); analytic, benchmark and ordering-pooled forecasts raise at h > 1 (b9c66c0 message; NOTES 8b); [V] b9c66c0 is an ancestor of the release commit 7f880e1
\item \textbf{C4, a backtest and verdict engine that encode ``volatility first''} (\crefrange{sec:eval-tests}{sec:eval-verdict}).
  Look-ahead-free refits, one-axis pairing, grid harmonisation, a three-MCSE gate, a validity policy for Diebold--Mariano tests with the Harvey--Leybourne--Newbold correction \citep{harvey1997testing}, model-confidence-set separation and a convergence gate \citep{vehtari2021rank} form one automatic rule; the combination is the claim, and its size and power were studied only after the release (\cref{app:dgp}). % after the release: PR #15 (benchmarks/reports/dgp_study.md, dgp_study_preregistration.md at 75e0c2a; records at 58ab09f, src = 4ac7969 plus validation/dgp.py), app:dgp; [V] src/rai_bvar/evaluation/compare.py (CompareResult.verdict: mc_multiple=3.0, min_converged=0.95); tests/integration/test_compare.py; tests/unit/test_grid_harmonise.py; no tests/dgp/ at 4ac7969 (dossier 01 §8.2)
\item \textbf{C5, validation as library code} (\cref{sec:validation}).
  \code{rai_bvar.validation} implements the statistics and independent reference models of identity checks, block-level checks, Geweke tests and simulation-based calibration (SBC), which with analytic twins, parity tests and a mutation suite form seven tiers \citep{geweke2004getting,cook2006validation,gelman2017correction,talts2018validating,modrak2025simulation,grosse2014testing,gandy2021unit,sailynoja2022graphical}. % [V] modules identities, geweke, sbc, uniformity, sequential, reference, simulate, log_joint, testfns, joint, dummies; tiers A, P, M live in tests/analytic, tests/parity, tests/mutation
  Geweke and SBC tests are registered for 23 composition rows, among them that of the replication's primary SV arm, and Geweke tests for 7 block configurations. % [V] at 7f410dc: src/rai_bvar/validation/joint.py _COMPOSITIONS (rows 1-18, 201-205; row 18 reduced_sv_rw is the Clark--Ravazzolo SV(rw) arm's composition); tests/geweke/test_geweke_compositions.py (test_g_full over COMPOSITIONS, test_g_small_block over BLOCK_CONFIGS); tests/sbc/test_sbc_compositions.py::test_sbc (row 18 at its per-row t_max = 400, SBC_OVERRIDES); [REL] pass records on the release commit: benchmarks/reports/validation/7f880e1_apple-m5-max/record/geweke.jsonl (23 G-full, 7 block), sbc.jsonl (23), all passed
  Mutation testing \citep{demillo1978hints,jia2011analysis} gives the identity, block-level, Geweke and SBC tiers a release gate: 18 curated sampler bugs, each with a confirmed catching tier, give 37 mutant-by-tier checks, all caught with passing controls; this is a regression gate, not an estimate of power. % [V] tests/mutation/mutants.py (catchers U, B, G, S only; 18 mutants, 37 checks; reproduced at 62d15f6, Apple M5 Max); [R] x86-64 Linux re-run of M1-M16, M17-M18 recorded on both platforms; [REL] record/mutation.jsonl at 7f880e1: 37 checks, all caught, every control passing
\item \textbf{C6, observations on validation methods} (\cref{sec:validation,sec:robustness-dummies}).
  Exact-mode SV is exact for any mixture table, so a coarse table gives Geweke tests power against exact-correction errors; % [V] NOTES 3; tests/mutation/mutants.py M7 (G with COARSE1 77.6 vs control 2.28; invisible with OCSN-10)
  the log-likelihood as a test quantity catches the triangular-step error of \citet{carriero2019large}, which parameter ranks missed in recorded runs, consistent with \citet{modrak2025simulation}; % [V] block SBC log-likelihood p 2.8e-11 vs control min p 0.10 (mutants.py M1); [R] whole-scan invariance "not caught" (q 0.29) and design-stage parameter-rank power at the nominal 1% (dossier 04 §7.5; NOTES 4)
  per-replication SBC effective sample sizes cannot be certified from 99 kept draws; % [V] DESIGN §9.6 erratum (NOTES 5)
  and dummy-observation rows admit a closed-form variance marginal and an exact rejection envelope. % [V] NOTES 13; tests/validation/test_reference_dummies.py
\item \textbf{C7, two float64 failures fixed in the kernel without jitter} (\cref{sec:robustness}).
  A Householder-QR draw of the contemporaneous coefficients replaces a Cholesky draw whose formed precision lost its small eigenvalue, and a cancellation-free excess-pivot recursion factorises the random-walk SV path system at $\sigma\approx5\times10^{-9}$; % [V] tests/mcmc/blocks/test_contemp_lstsq.py (docstring l.4-6); tests/mcmc/blocks/test_sv_core.py::test_rw_awol_at_a_tiny_sigma
  we claim this application of subtraction-free elimination \citep{grassmann1985regenerative,alfa2002accurate,ye2008computing,demmel2008accurate}, not the algorithm. % [R] Demmel et al. arXiv 0712.4027 sec. 2.3.4 (https://arxiv.org/pdf/0712.4027); see sec:samp-rw
\item \textbf{C8, reproducible JAX MCMC with stated limits} (\cref{sec:arch-repro}).
  Counter-based random keys \citep{salmon2011parallel} are derived per chain, sweep, block and equation; % [V] src/rai_bvar/engines/mcmc/keys.py docstring (typed threefry2x32; fold_in by chain, absolute sweep, Block, equation); DESIGN §5.6 (D-16)
  invariances are tested bitwise on toy kernels and on production chain prefixes under \code{chains="map"}, and to a relative $10^{-9}$ for production \code{vmap} and \code{shard_map} runs; nothing is guaranteed across platforms or JAX versions. % [V] tests/mcmc/runner/test_chunking.py::test_chunk_and_burn_piece_size_invariance (toys), ::test_mapped_chains_production_prefix (production structural_sv, bitwise), ::test_production_chain_prefix_with_vmapped_chains_to_rounding (rtol 1e-9); test_sweep.py::test_fused_equals_unfused_bitwise (toys); test_devices_bitwise.py::test_shard_map_matches_vmap_in_subprocess (production structural_sv, rtol 1e-9); DESIGN §5.6 ("Not across JAX versions, platforms ...")
\item \textbf{C9, an empirical illustration} (\cref{sec:replication}).
  A pre-registered qualitative replication of \citet{clark2015macroeconomic} on FRED-QD with all 24 variable orderings illustrates the workflow; it does not test the econometric claim.
  In a first full run \fullrun{criteria 1, 2, 3 and 5 of six were met and criteria 4 and 6 were not}, which we traced to marginal $\hat R$ misses at the convergence gate and to the tail failure of the path-conditioned score at a few crisis origins. % [FULL] criteria[*].met (report commit 551f181, path-conditioned estimator); [PREREG] "Why there is a second run" (criterion 6 failed only on the gate; base-budget misses all on sigma, R-hat < 1.03; criterion 4 driven by a handful of 2007-08 origins)
  The acceptance run's settings respond to that diagnosis, so its pre-registration is not blind, but they were committed before the run was launched. % [PREREG] benchmarks/reports/clark_ravazzolo_preregistration.md (c823d20), "Why there is a second run"; launch after c823d20: [ACC: versions.git_commit = c823d20, versions.git_dirty = false]; [R] committed run log (65dd212), start 16:10:56Z after the c823d20 commit time 16:10:45Z
  As coded, its outcome is: \acc{criteria[*].met}. With every reduced-form fit converged on the gate's primary quantities, stochastic volatility is ``better'' at $h = 1$ in all 24 orderings. Criterion~4 fails because the path-integrated RB unemployment gain is larger at $h = 8$ (\acc{relative.full['SV(rw)'].variables.UR['8'].dlps}) than at $h = 1$ (\acc{relative.full['SV(rw)'].variables.UR['1'].dlps}); about 72\% of the $h = 8$ sum comes from three crisis origins, and on Clark and Ravazzolo's Gaussian-approximation score the gain shrinks, as in their results, although the criterion then fails on pre-crisis GDP instead (\cref{sec:replication-results}). We report this difference without tuning and leave its causes as untested hypotheses. % [ACC: criteria[*].met; min(converged[*][*]) (primary monitor set, src/rai_bvar/engines/mcmc/monitor.py); criteria[id=6].detail; criteria[id=4].detail (UR Gaussian h1 +0.122 -> h8 -0.526; pre-crisis GDP h8 Gaussian -0.001)]; 72%: recomputed from relative.full['SV(rw)'].variables.UR['8'].{dlps_top, dlps, n} (20.74 of 28.89 nats); [R] CR_FULL l.147 (UR h = 8: -0.707); [PREREG] "Stated in advance"
\end{itemize}
