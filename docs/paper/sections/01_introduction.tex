\section{Introduction}\label{sec:intro}

% ---------------------------------------------------------------- P1: the question
\pkg{rai-bvar} is a Python package for Bayesian vector autoregressions (BVARs) built around one question, stated in its specification as
\begin{quote}
``Does added model complexity improve out-of-sample density forecasts once time-varying volatility is accounted for?''
\end{quote}
% [R] SPEC.md §1.1 (l.27-39), quoted verbatim
The qualification matters.
The volatility of U.S. macroeconomic shocks has changed over the post-war period \citep{cogley2005drifts,primiceri2005time,sims2006were}, and allowing for time-varying volatility has been found to improve BVAR density forecasts \citep{clark2011realtime,clark2015macroeconomic,carriero2016common}; \citet{chan2024bvars} surveys BVARs with stochastic volatility (SV), and \citet{carriero2015bayesian} study how other specification choices affect forecast accuracy.
When a model with a richer mean or prior is compared with a baseline that also has a different volatility specification, the measured gain combines the two changes.
The package therefore adopts a design position, which is a rule of the software and not an empirical finding: a mean or prior effect is measured with the volatility specification held fixed, so a richer mean or prior under SV is compared with the linear Minnesota model under the same SV, never with a constant-volatility baseline. % [R] SPEC.md R2 "Volatility first (fair ablation)" (l.109)

% ---------------------------------------------------------------- P2: six threats (the thesis)
The credibility of such a comparison depends on six links.
We state each as a requirement on the software, not as a claim about existing tools, and point to where this paper addresses it.
\begin{enumerate}
\item \emph{The sampler may target the wrong posterior.}
  A published equation-by-equation sampler for large BVARs with SV \citep{carriero2019large} did so, as \citet{bognanni2022comment} showed; \citet{carriero2022corrigendum} corrected it.
  Samplers need checks of known power (\cref{sec:validation}).
\item \emph{Every forecast origin is a separate MCMC fit, and each must converge}; a gain computed from unconverged fits should not be certified (\cref{sec:eval-verdict,sec:validation-convergence,sec:replication-prereg}).
\item \emph{The log score is itself a Monte Carlo estimate.}
  At horizons beyond one step its error can be large in the tails while the reported standard error stays small (\cref{sec:eval-tail}). % [R] NOTES 8b (Clark--Ravazzolo crisis origins, h = 8)
\item \emph{Triangular SV models depend on the variable ordering} \citep{arias2023macroeconomic,chan2024large}, so a gain should be reported with its spread across orderings (\cref{sec:eval-ordering,sec:replication-results}).
\item \emph{Tests must be valid for the design.}
  For nested models under an expanding window, tests of equal predictive accuracy in the tradition of \citet{diebold1995comparing} lack their standard limiting distribution \citep{clark2001tests}, and the framework of \citet{giacomini2006tests} requires a rolling or fixed window.
  A decision then needs a second route, here the model confidence set \citep{hansen2011model}, and the scores compared must be proper \citep{gneiting2007strictly} (\cref{sec:eval-tests}).
\item \emph{Analysis choices can be made after the scores are seen}, unless the settings are fixed in code before the scores exist (the pre-registration in \cref{sec:replication-prereg}).
\end{enumerate}
Two infrastructure requirements follow: one estimation interface and output format for conjugate and non-conjugate models (\cref{sec:arch-resolution,sec:eval-contract}), and no look-ahead, so that data-dependent prior settings such as Minnesota scales are recomputed inside every estimation window (\cref{sec:eval-backtest}). % [R] SPEC.md R9

% ---------------------------------------------------------------- P3: what rai-bvar is
The package metadata describe \pkg{rai-bvar} as ``Ablation-ready Bayesian VARs: composable mean, volatility and prior components with a fair out-of-sample verdict engine.'' % [V] pyproject.toml [project] description, verbatim
Five design commitments shape it.
(i)~The composition chooses the engine: conjugate Minnesota models, including the hierarchy of \citet{giannone2015prior} and the COVID-19 scaling of \citet{lenza2022estimate}, go to an analytic engine, and compositions with SV, outliers or Student-$t$ errors to hand-written JAX Gibbs samplers; the user never selects the engine.
(ii)~Both engines return one predictive contract.
(iii)~One backtest engine and one verdict engine score and compare every model.
(iv)~Validation ships as library code (\code{rai_bvar.validation}), not only as tests.
(v)~The implementation is licensed under Apache-2.0, and GPL-licensed packages were run only as numerical oracles, with the qualification given in \cref{sec:related}. % [V] SPEC.md R1, R3; src/rai_bvar/api.py (no user-settable engine field); src/rai_bvar/validation/; LICENSE
``Ablation-ready'' describes the architecture, in which a new mean, volatility or prior component is evaluated against every existing one through one contract and one verdict rule.
The release described here (Phases 0--2 of the roadmap) populates the volatility axis; the mean axis is linear and the prior axis is the Minnesota family (\cref{sec:framework}). % [V] dossier 01 §2.1; src/rai_bvar/validation/joint.py l.454-480
It is version 0.0.1, classified as pre-alpha. % [V] pyproject.toml version, classifier "Development Status :: 2 - Pre-Alpha"

% ---------------------------------------------------------------- P4: contributions
Our thesis is that a model comparison is only as credible as its weakest link: the sampler, convergence, the Monte Carlo error of the score, the variable ordering, test validity, or post-hoc choices.
\pkg{rai-bvar} makes each link checkable, and this paper shows the evidence for each.
The econometrics is not new; the contribution is the integration, the contracts and the evidence of correctness:
\begin{itemize}
\item \textbf{C1, a factorial composition grammar} (\cref{sec:architecture}).
  \code{BVAR(mean=...,vol=...,lags=...)} resolves to an engine by fixed rules, rejects invalid compositions at construction, and exposes \code{spec()} and \code{axes}; together with the hash \code{spec_hash(model)} they make ``differs along exactly one axis'' a checkable property. % [V] src/rai_bvar/api.py (BVAR.spec, BVAR.axes); src/rai_bvar/models/base.py l.57 (spec_hash is a module function, not a BVAR attribute); tests/unit/test_api_resolution.py::test_resolution_table, ::test_sv_arms_differ_from_constant_along_the_vol_axis_only
\item \textbf{C2, a populated volatility axis} (\cref{sec:framework}).
  The release provides constant volatility under inverse-gamma, inverse-Wishart or IW-equivalent \citep{chan2022asymmetric} priors, and SV with AR(1) or random-walk log-variance, with outliers \citep{carriero2024addressing}, with Student-$t$ errors \citep{jacquier2004bayesian}, or with both, in two recursive structural forms and the corrected reduced form \citep{carriero2022corrigendum}, though not every combination in every form (\cref{sec:framework:delivered}); dummy-observation priors \citep{doan1984forecasting,sims1998bayesian,giannone2015prior} are available on both engines. % [V] src/rai_bvar/validation/joint.py l.454-480 (rows 1-17, 201-205); src/rai_bvar/api.py docstring (inverse-Wishart only in structural Mode II; reduced x Constant("iw") raises); dossier 01 §2.1
\item \textbf{C3, one predictive contract} (\crefrange{sec:eval-contract}{sec:eval-tail}).
  Path draws with per-draw conditional means and Cholesky factors give a Rao--Blackwellised log score with analytic marginalisation and an effective-sample-size-adjusted Monte Carlo standard error (MCSE), following \citet{geweke2010comparing} and \citet{kruger2021predictive}. % [V] src/rai_bvar/forecast/result.py::log_pred_density (delta-method MCSE times sqrt(S/ESS) on MCMC forecasts, l.323-338); tests/contract/test_forecast_contract_mcmc.py::test_log_pred_density
  The contract's simulation-consistency invariant is tested for every registered analytic model and for 12 MCMC compositions. % [V] tests/contract/test_forecast_contract.py, test_forecast_contract_mcmc.py::test_simulation_consistency; tests/mcmc/forecast/mcmc_fits.py COMPOSITIONS (12 entries)
  We diagnose a tail failure of the path-conditioned estimator at $h>1$ and add, for MCMC forecasts, an opt-in estimator that integrates the intermediate outcomes out. % [R] NOTES 8b; [V] D-34 tests at b9c66c0 (tests/unit/test_lpd_integrated.py, tests/mcmc/forecast/test_lpd_integrated_mcmc.py); analytic, benchmark and ordering-pooled forecasts raise at h > 1 (b9c66c0 message; NOTES 8b); [REL]
\item \textbf{C4, a backtest and verdict engine that encode ``volatility first''} (\crefrange{sec:eval-tests}{sec:eval-verdict}).
  Look-ahead-free refits, one-axis pairing, grid harmonisation, a three-MCSE gate, a validity policy \citep{clark2001tests,giacomini2006tests} for Diebold--Mariano tests with the Harvey--Leybourne--Newbold correction \citep{diebold1995comparing,harvey1997testing}, model-confidence-set separation \citep{hansen2011model} and a convergence gate \citep{vehtari2021rank} combine into one automatic rule.
  The combination is the claim; the rule's size and power are not yet studied (\cref{sec:limitations}). % [V] src/rai_bvar/evaluation/compare.py (CompareResult.verdict: mc_multiple=3.0, min_converged=0.95); tests/integration/test_compare.py; tests/unit/test_grid_harmonise.py; no tests/dgp/ (dossier 01 §8.2)
\item \textbf{C5, validation as library code} (\cref{sec:validation}).
  The validation package (4,230 lines) implements the statistics and the independent reference models of identity checks, block-level checks, Geweke tests and simulation-based calibration (SBC); with the analytic twins, parity tests and mutation suite of the test suite they form seven tiers \citep{geweke2004getting,cook2006validation,gelman2017correction,talts2018validating,modrak2025simulation,grosse2014testing,gandy2021unit,sailynoja2022graphical}. % [V] wc -l src/rai_bvar/validation/*.py = 4230 (HEAD d58c9ef); modules identities, geweke, sbc, uniformity, sequential, reference, simulate, log_joint, testfns, joint, dummies; tiers A, P, M live in tests/analytic, tests/parity, tests/mutation
  The reference modules import no kernel code, which a test enforces, and Geweke and SBC tests are registered for 22 composition rows and Geweke tests for 7 block configurations. % [V] tests/validation/test_log_joint.py::test_references_never_import_kernels; tests/geweke/test_geweke_compositions.py (test_g_full over COMPOSITIONS, test_g_small_block over BLOCK_CONFIGS); tests/sbc/test_sbc_compositions.py::test_sbc; pass records on the release commit [REL]

  The power of the identity, block-level, Geweke and SBC tiers is measured by mutation testing \citep{demillo1978hints,jia2011analysis}: 18 injected sampler bugs give 37 mutant-by-tier checks, all caught with passing controls. % [V] tests/mutation/mutants.py (catchers U, B, G, S only; 18 mutants, 37 checks; reproduced at 62d15f6, Apple M5 Max); [R] x86-64 Linux re-run of M1-M16, M17-M18 recorded on both platforms; [REL]
  On testing probabilistic programming systems, see \citet{dutta2018testing}.
\item \textbf{C6, observations on validation methods} (\cref{sec:validation,sec:robustness-dummies}).
  Exact-mode SV is exact for any mixture table, so a deliberately coarse table gives Geweke tests power against errors in the exact correction; % [V] NOTES 3; tests/mutation/mutants.py M7 (G with COARSE1 77.6 vs control 2.28; invisible with OCSN-10)
  the log-likelihood as a test quantity catches the triangular-step error of \citet{carriero2019large}, which parameter ranks missed in recorded runs, consistent with \citet{modrak2025simulation}; % [V] block SBC log-likelihood p 2.8e-11 vs control min p 0.10 (mutants.py M1); [R] whole-scan invariance "not caught" (q 0.29) and design-stage parameter-rank power at the nominal 1% (dossier 04 §7.5; NOTES 4)
  per-replication SBC effective sample sizes cannot be certified from 99 kept draws; % [V] DESIGN §9.6 erratum (NOTES 5)
  and dummy-observation rows admit a closed-form variance marginal and an exact rejection envelope. % [V] NOTES 13; tests/validation/test_reference_dummies.py
\item \textbf{C7, two float64 failures fixed in the kernel without jitter} (\cref{sec:robustness}).
  A Householder-QR draw of the contemporaneous coefficients replaces a Cholesky draw whose formed precision, with eigenvalues $1.9\times10^{17}$ and $14.8$ at a failing Geweke state, lost the small one, and a cancellation-free excess-pivot recursion factorises the random-walk SV path system at $\sigma\approx5\times10^{-9}$.
  The recursion applies subtraction-free elimination \citep{grassmann1985regenerative,alfa2002accurate,ye2008computing}; we claim the application, not the algorithm. % [V] tests/mcmc/blocks/test_contemp_lstsq.py (docstring l.4-6); tests/mcmc/blocks/test_sv_core.py::test_rw_awol_at_a_tiny_sigma
\item \textbf{C8, reproducible JAX MCMC with stated limits} (\cref{sec:arch-repro}).
  Random keys are counter-based \citep{salmon2011parallel} and derived per chain, sweep, block and equation. % [V] src/rai_bvar/engines/mcmc/keys.py docstring (typed threefry2x32; fold_in by chain, absolute sweep, Block, equation); DESIGN §5.6 (D-16)
  Bitwise invariances are tested with their scope stated: toy kernels for chunking and plans, production chain prefixes under \code{chains="map"}. % [V] tests/mcmc/runner/test_chunking.py::test_chunk_and_burn_piece_size_invariance (toys), ::test_mapped_chains_production_prefix (production structural_sv, bitwise); test_sweep.py::test_fused_equals_unfused_bitwise (toys)
  Production chain prefixes under \code{chains="vmap"} and production \code{shard_map} runs agree with their references to a relative tolerance of $10^{-9}$, and nothing is guaranteed across platforms or JAX versions. % [V] test_chunking.py::test_production_chain_prefix_with_vmapped_chains_to_rounding (rtol 1e-9); test_devices_bitwise.py::test_shard_map_matches_vmap_in_subprocess (production structural_sv, rtol 1e-9); DESIGN §5.6 ("Not across JAX versions, platforms ...")
\item \textbf{C9, an empirical illustration} (\cref{sec:replication}).
  A pre-registered qualitative replication of \citet{clark2015macroeconomic} on FRED-QD with all 24 variable orderings illustrates the workflow; it does not test the econometric claim.
  In a first full run \fullrun{criteria 1, 2, 3 and 5 of six were met and criteria 4 and 6 were not}; the diagnosis was that marginal $\hat R$ misses let the convergence gate decide one criterion and that the path-conditioned score degenerated at a few crisis origins, which drove the other. % [FULL] criteria[*].met (report commit 551f181, path-conditioned estimator); [PREREG] "Why there is a second run" (criterion 6 failed only on the gate; base-budget misses all on sigma, R-hat < 1.03; criterion 4 driven by a handful of 2007-08 origins)
  The settings were chosen in response to that diagnosis, so the pre-registration is explicitly not blind; what it fixes is that they were committed before the acceptance run was launched, before any of its scores existed. % [PREREG] benchmarks/reports/clark_ravazzolo_preregistration.md (c823d20), "Why there is a second run"; launch after c823d20 is [R] (OUTLINE §0.4; run log, TODO 2) until [ACC: versions.git_commit, versions.git_dirty] confirm it
  The acceptance run's outcome is \acc{criteria[*].met}.
\end{itemize}
