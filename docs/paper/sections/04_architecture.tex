\subsection{Design rules}\label{sec:arch-rules}

Nine design rules fix the shape of the package. % [R] SPEC.md §3 (R1–R9)
Five shape the interface: composition over inheritance (R1: a model is \code{BVAR(mean, vol, ...)},
with no model-specific classes), volatility first (R2), one predictive contract for both engines
(R3), the variable ordering surfaced rather than hidden (R8), and no look-ahead (R9; \cref{sec:eval-backtest}). % R9's gloss ("everything data-dependent is recomputed inside each estimation window") deleted here: duplicated in §1 (sec:intro, "no look-ahead, so that data-dependent prior settings ... are recomputed inside every estimation window")
Three govern the internals: float64 throughout, no explicit inverses, precision-based samplers and
log-space densities (R4); no sampler merged without passing Geweke and simulation-based calibration
tests (R6; \cref{sec:validation}); and one MCMC backend, hand-written Gibbs kernels in JAX
\citep{bradbury2018jax,frostig2018compiling} with no probabilistic programming language in the core
(R7).
R5 concerns licensing (\cref{sec:related}).
\cref{fig:architecture} shows the resulting layers.

\subsection{Composition and engine resolution}\label{sec:arch-resolution}

A model is a frozen dataclass \code{BVAR(mean, vol, lags, deterministic, outliers, mcmc)} with no
engine field.
Its constructor resolves the \code{"auto"} defaults, applies nine rules that map a resolved
(prior form, volatility prior) to an engine and mode, and, for MCMC compositions, rejects what the
engine does not support (\cref{tab:resolution} in \cref{app:resolution}): a conjugate prior runs
on the analytic NIW engine with \code{Constant("iw")} and is an error with any other volatility; a
structural prior runs on the MCMC engine, in Mode~II (the NIW twin) with \code{Constant("iw")}, with
the $(a, \lambda)$ prior of \citet{chan2022asymmetric} under \code{Constant("iw_equivalent")} and in
Mode~I otherwise; and a reduced-form prior runs the corrected triangular step on the MCMC engine,
except with \code{Constant("iw")}, which is an error. \code{BVAR()}, \code{BVAR(vol=Constant("ig"))}
and \code{BVAR(vol=SV())} reach the first, the structural Mode~I \code{Constant} and the structural
Mode~I SV rules. % [V] the next tag; src/rai_bvar/api.py (_resolve_auto, engine); the detail and its [R] tag are in app:resolution, Tab2 moved there in the integration pass
Every error is raised at construction, and tests check every rule of the table (the seven
non-error rules case by case) and every error. % [V] src/rai_bvar/api.py (BVAR.__post_init__, _resolve_auto, _check_mcmc_rules); tests/unit/test_api_resolution.py::test_resolution_table (rows 1, 3–8), ::test_conjugate_form_with_any_other_volatility_raises (row 2), ::test_reduced_form_with_the_conjugate_iw_prior_raises (row 9), ::test_lenza_primiceri_scaling_is_rejected_on_mcmc, ::test_metropolis_hastings_hierarchy_is_rejected_on_mcmc, ::test_structural_eb_over_psi_with_cross_shrinkage_is_rejected


\code{spec()} returns plain JSON and \code{from\_spec(spec())} round-trips (a property-based
test). % [V] tests/unit/test_spec_roundtrip_mcmc.py::test_from_spec_inverts_spec_for_random_mcmc_compositions (hypothesis)
Because the resolved components are stored, \code{BVAR()} still resolves to the Phase~1 composition,
and every Phase~1 (conjugate) model keeps the specification hash, name and axes recorded with the
Phase~1 code (golden tests). % [V] tests/unit/test_phase1_hash_golden.py::test_default_spec_is_byte_identical_to_phase1, ::test_auto_defaults_resolve_to_the_phase1_composition, ::test_phase1_models_keep_their_spec_hash_name_and_axes (values recorded at cbfcc5b)
The property \code{axes} splits a model into mean, prior, volatility, lags, deterministic terms and
outliers, and each axis label encodes every non-default setting, so ``differs along exactly one
axis'' is a property that \code{compare()} checks (\cref{sec:eval-verdict}); the Mode~II prior label
\code{scaling=conjugate} keeps a Mode~II model from being paired with a Mode~I model along the
volatility axis. % [V] tests/unit/test_api_resolution.py::test_mode_two_prior_axis_carries_the_conjugate_scaling
\code{import rai\_bvar} imports no JAX (a subprocess test checks this); the MCMC engine is loaded at
the first MCMC fit. % [V] tests/mcmc/unit/test_import_no_jax.py; tests/unit/test_api_resolution.py::test_mcmc_compositions_are_built_and_described_without_jax

\subsection{The analytic engine}\label{sec:arch-analytic}

The conjugate engine uses NumPy \citep{harris2020array} and SciPy \citep{virtanen2020scipy}.
One QR decomposition of the stacked Minnesota dummy rows, SOC/SUR rows and data gives the posterior;
$(R^\top R)^{-1}$ is never formed, and draws use the Bartlett decomposition.
Empirical Bayes maximises the log marginal likelihood plus the log hyperprior by L-BFGS-B, and the
hierarchical option is the random-walk Metropolis--Hastings scheme of \citet{giannone2015prior}. % [V] src/rai_bvar/engines/analytic.py (dossier 02 §5.1, §5.3)
The engine also computes recursive impulse responses and the forecast-error variance decomposition.

\subsection{The MCMC engine in six ideas}\label{sec:arch-mcmc}

\begin{enumerate}[leftmargin=*,itemsep=2pt,topsep=4pt]
  \item \emph{The static/traced split is the compilation cache key.} Choices that fix a shape or a
    branch live in a frozen, hashable \code{StaticConfig}; data, priors, hyperparameters, seeds and
    the sample length are traced. Time is padded, by default to $T_{\mathrm{pad}} = 32\lceil T/32\rceil$, with
    zero-weight rows, so backtest windows in one bucket share compiled programs; a test of two such
    windows sees no recompilation. % [V] src/rai_bvar/engines/mcmc/config.py; tests/mcmc/runner/test_recompile.py::test_zero_recompiles_across_windows_of_one_bucket (runner toys). "masked before any logarithm" deleted here as duplicated in alg:C-vol (Appendix C, "mask before the log (erratum E23)") and Appendix I (E23)
  \item \emph{Equations and chains are \code{vmap} axes.} Given the volatilities the structural
    equations are conditionally independent, so kernels are written for one equation and batched,
    and the batched phase is an exact Gibbs block. Chains run under \code{vmap} (default),
    \code{lax.map} or \code{shard\_map}.
  \item \emph{The Gibbs order is data.} A \code{Plan} of \code{Step}s with declared read and write sets
    is printed by \code{fit.plan.describe()} (\cref{fig:FigC1}). Invariants are checked for every
    composition, including a tree diff showing that each step writes only what it declares. The mixture
    indicators are local to the volatility step, so nothing is drawn between them and the log
    volatilities \citep{delnegro2015time}. % [V] tests/mcmc/runner/test_plan.py::test_plan_invariants_every_composition_with_tree_diff, ::test_plan_invariants_production_kernels, ::test_tree_diff_catches_undeclared_write
  \item \emph{Kernels are pure and take injected noise:} \code{sample\_core(draw\_noise(key, ...), ...)}.
    Every exact draw exposes its conditional and every Metropolis--Hastings step its log acceptance
    ratio; the identity tests of \cref{sec:validation} use both, and the failure replay
    evaluates the conditionals. % [R] DESIGN §3.1 rules 2–3; [V] e.g. tests/mcmc/blocks/test_sv_core.py::test_exact_h_log_accept_identity
  \item \emph{Randomness is counter-based} \citep{salmon2011parallel}. Keys are \code{fold\_in} chains
    over stream, data salt, chain, absolute sweep, block, equation and sub-draw, with unsigned 32-bit
    counters and no key in any loop carry, so a draw depends on its position in the chain, not on how
    sweeps are grouped into compiled calls. % [V] src/rai_bvar/engines/mcmc/keys.py; tests/mcmc/runner/test_sweep.py::test_counter_must_be_uint32
  \item \emph{Failures are values.} Nothing raises inside compiled code and no jitter is added. Each
    chain keeps its first failure as $(\text{code}, it)$ (\cref{alg:sweep}); the host replays the failing chunk deterministically, evaluates the failing
    block's exposed conditional, and raises \code{MCMCNumericalError} with the block, equation,
    iteration and diagnostics. No chain is dropped. % [V] tests/mcmc/runner/test_failures.py::test_failure_in_burn_in_is_replayed, ::test_failure_in_sampling_is_replayed, ::test_replay_of_an_equation_failure_after_the_production_cccm_step
    \cref{sec:robustness} describes such failures.
\end{enumerate}

\subsection{Settings and runtime}\label{sec:arch-settings}

\code{MCMCSettings} is part of the specification: by default 4 chains after a burn-in of 1000, with
10,000 kept draws per chain for a composition with stochastic volatility and 2000 otherwise, and
convergence thresholds $\hat R < 1.01$ and bulk ESS $> 400$ (\cref{sec:eval-verdict}); an SV fit with
fewer kept draws warns (\cref{sec:limitations}). % [V] src/rai_bvar/settings.py at 4ac7969 (MCMCSettings fields and docstring; draws=None resolved by BVAR to default_draws(sv): SV_DEFAULT_DRAWS = 10_000, DEFAULT_DRAWS = 2_000; design decision D-35, e8cf9f1, PR #7); warning: src/rai_bvar/engines/mcmc/resolve.py (sv_budget), monitor.py::sv_budget_message; tests/unit/test_default_budget.py (passed on Linux in CI run 40061724239 at 7f880e1; tests/unit is not in the Apple release record); the walk-through's explicit 4 x 1000 triggers it (docs/paper/code/out/ex_b.stderr.txt)
\code{Runtime} is not: it holds the device count (default 1), the kept draws per compiled call, a memory
budget checked only before sampling, a memory-mapped store and the replay option. % [V] src/rai_bvar/settings.py (Runtime); tests/mcmc/runner/test_storage.py::test_run_raises_over_budget_before_sampling
The backtest never passes a \code{Runtime}, so cached scores do not depend on the machine's device
count. % [R] DESIGN §5.2; [V] src/rai_bvar/evaluation/backtest.py passes no Runtime
An \code{MCMCFit} holds the draws as an xarray \code{DataTree} \citep{hoyer2017xarray}, diagnostics,
a \code{summary()} (prior mode, hyperparameters, implied reduced-form prior moments, ordering), the
\code{converged} flag, \code{forecast()}, \code{irf()} and the final state for warm starts.

\subsection{Extension protocol}\label{sec:arch-extension}

New components implement \code{MeanBlock}, \code{VolBlock}, \code{CoefPrior} or \code{GlobalStep} and
register an independent reference implementation, from which the validation package builds their
per-block and per-composition Geweke configurations. % [V] src/rai_bvar/engines/mcmc/protocols.py; src/rai_bvar/validation/reference.py (module docstring "Registry"; register_reference)
That later components will plug in without editing the sweep, runner or forecast core is a design
intention, not yet tested. % [R] DESIGN §3.9 (dossier 01, unsupported claim 3)
