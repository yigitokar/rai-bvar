\section{Related software, numerical oracles and licensing}\label{sec:related}

% ---------------------------------------------------------------- P1: packages in their Phase 0-2 roles
Existing packages had the following roles, with the versions used (parity results are in \cref{sec:validation-parity}).
The R package \pkg{BVAR} \citep{kuschnig2021bvar}, version 1.0.5 \citep{kuschnig2024bvar}, was run as the oracle for the hierarchical prior of \citet{giannone2015prior}, for the sum-of-coefficients and single-unit-root dummy observations, and for Metropolis--Hastings sampling of the hyperparameters, % [V] tests/parity/test_r_bvar.py; fixtures tests/parity/fixtures/r_bvar_*.json; tests/parity/BVAR_PARAMETRIZATION.md "Versions" (R 4.1.2, BVAR 1.0.5)
and the Python package \pkg{bvar} of the Bank of England \citep{labonne2026bvar}, version 0.3.5 (MIT licence), as a second oracle for the analytic engine. % [V] tests/parity/test_boe_bvar.py; tests/parity/BOE_BVAR_NOTES.md header
\pkg{stochvol} \citep{kastner2016dealing,hosszejni2021modeling}, version 3.2.1, was run as the oracle for univariate SV (\cref{app:parity}). % [V] tests/parity/test_stochvol.py; tests/parity/SV_PARAMETRIZATION.md "Versions"
\pkg{bayesianVARs} \citep{gruber2026bayesianvars}, version 0.1.8, was planned as the oracle for the corrected reduced-form sampler but could not be built without a Fortran compiler before the release; \cref{sec:validation-parity} describes its substitute, \cref{app:parity} a later run. % after the release: app:parity (PR #21, merged dfcaf12; binary packages, black box); [R] DESIGN.md Stage 4 amendment (2); SV_PARAMETRIZATION.md §4; fixtures probe_bayesianvars.nc (bayesianvars_available = 0) and bvars_swa_*.nc; tests/parity/test_bayesianvars.py
\pkg{bvartools} \citep{mohr2026bvartools} was an architectural reference, never run, % [V] tools/make_r_fixtures.R loads only jsonlite, BVAR, coda, stochvol (l.87-92) and probes bayesianVARs
and none of the later-phase oracles, \pkg{factorstochvol} \citep{kastner2026factorstochvol}, \pkg{bvars} \citep{liu2026bvars}, \pkg{bsvars} \citep{wozniak2026bsvars}, \pkg{bsvarSIGNs} \citep{wang2026bsvarsigns} and \pkg{bvarsv} \citep{krueger2015bvarsv}, was run before the release. % after the release, bvars 1.1 was run as a black box in WP29 (PR #21, merged dfcaf12; [V] fixture tests/parity/fixtures/wbvars_csv.nc attrs bvars_version 1.1, ci_run 40243289623), no finding about it is stated here; bsvars 4.0 and factorstochvol 1.1.2 were only installed in that job; [R] SPEC.md §2.2 (Phases 3, 5, 6); the sources of some were read for constants (app:licensing), so "run", not "used"

% ---------------------------------------------------------------- P3: what the package builds on
The MCMC engine is written in \pkg{JAX} \citep{bradbury2018jax,frostig2018compiling}, the analytic engine in \pkg{NumPy} \citep{harris2020array} and \pkg{SciPy} \citep{virtanen2020scipy}, forecasts and MCMC posteriors are returned as \pkg{xarray} objects \citep{hoyer2017xarray}, and the continuous ranked probability score (CRPS), its threshold-weighted version and the energy and variogram scores come from \pkg{scoringrules} \citep{zanetta2024scoringrules} (in R, \pkg{scoringRules}; \citealp{jordan2019evaluating}). % [V] pyproject.toml [project] dependencies; src/rai_bvar/evaluation/scores.py (sr.crps_ensemble, sr.twcrps_ensemble, sr.es_ensemble, sr.vs_ensemble); src/rai_bvar/forecast/result.py (xr.Dataset), src/rai_bvar/engines/mcmc/results.py (DataTree); analytic engine has no xarray posterior
The samplers are hand-written Gibbs kernels by design, not models in a probabilistic programming language such as \pkg{PyMC} \citep{abrilpla2023pymc} or \pkg{NumPyro} \citep{phan2019composable}; % [R] SPEC.md R7
each exposes its exact conditional or Metropolis--Hastings acceptance ratio, on which the identity tests (\cref{sec:validation-u}) and the deterministic replay of failures (\cref{sec:architecture}) rely; we make no claim about relative mixing. % [V] src/rai_bvar/validation/identities.py docstring; [R] DESIGN §5.7 (D-18: the host replays the failing chunk and evaluates the failing block's exposed conditional); no NUTS comparison exists in the repository (dossier 01, unsupported item 2)

% ---------------------------------------------------------------- P4: licensing and the practice, exact wording
\pkg{rai-bvar} is released under the Apache License, version 2.0. % [V] LICENSE; pyproject.toml license = "Apache-2.0"
The R oracles \pkg{BVAR} (GPL-3) and \pkg{stochvol} (GPL~$\geq$~2) are GPL-licensed, so the project's specification requires algorithms to be implemented from the published papers, not translated from GPL source. % [R] tests/parity/BVAR_PARAMETRIZATION.md l.3 (GPL-3); docs/phase2/03_sv_outliers_t.md l.9 (stochvol GPL >= 2); SPEC.md §2.1
% [R] CRAN License fields read 2026-10-23: https://cran.r-project.org/web/packages/BVAR/index.html (1.0.5, GPL-3 | file LICENSE), https://cran.r-project.org/web/packages/stochvol/index.html (3.2.9, GPL (>= 2)); versions run: https://raw.githubusercontent.com/cran/BVAR/1.0.5/DESCRIPTION (GPL-3), https://raw.githubusercontent.com/cran/stochvol/3.2.1/DESCRIPTION (GPL (>= 2)). The other R packages of this section are GPL on CRAN except bvhar (MIT + file LICENSE, P2 only); no licence claim is made for them here (P2 makes none)
The development practice was:
\begin{quote}
No code was translated from GPL sources. Algorithms were implemented from the published papers. GPL packages were run as numerical oracles, and in a few documented cases (named in the repository notes) their source was read to pin down an oracle's behaviour, defaults or constants, never to write implementation code.
\end{quote}
% [V] wording verbatim from dossier 01 §6.2; the practice is recorded in the notes listed in tab:H-notes
This is weaker than a clean-room process in the strict sense, in which implementers never see the source, and we do not claim that stronger property; \cref{tab:H-notes} in \cref{app:licensing} lists the five repository notes that record a reading of GPL source, with the version read and the purpose. % [V] docs/phase2/02_sv_sampler.md l.6, l.597-608; 01_omori_mixture.md l.9-11; 03_sv_outliers_t.md l.6-9; 07_jax_patterns.md l.736, l.764; tests/parity/BVAR_PARAMETRIZATION.md l.3-13
The FRED-MD and FRED-QD databases \citep{mccracken2016fredmd,mccracken2021fredqd} are downloaded on demand and checked against SHA-256 checksums, never bundled, because some series carry third-party copyrights. % [R] SPEC.md §5.8 (l.328-329), decision D4; src/rai_bvar/datasets/fred.py
